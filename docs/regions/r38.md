## What other regions must know

### Selectors are blobs, passed by pointer

- A `CSS::Selector` (ref-counted in C++) is a managed blob made by `css_selector_create(compounds)`
  (`new`), handled as `CssSelector*`. The two C++ `mutable` caches (`m_specificity`,
  `m_sibling_invalidation_distance`) are written through a cast of the const receiver.
- **`Selector const&` is `const CssSelector*`** in every r38 function (DESIGN §2.2: const stays on
  value types passed by pointer). The :has() result cache keys on the selector's *address*
  (`HasResultCacheKey { &selector, &anchor }`), so a by-value `CssSelector` (as the generated
  stubs had it) would give every argument selector the same stack address. **r39, r42**: your
  stubs that take `selector: CssSelector` (`should_reject_with_ancestor_filter`,
  `collect_selector_insights`, `build_invalidation_sets_for_selector`, …) should do the same when
  ported; call r38 with the `CssSelector*` you hold.
- The other `const&` value types of the private engine functions (SimpleSelector,
  CompoundSelector, PseudoClassSelector, Attribute, QualifiedName) are `const T*`.
  `AbstractElement const&` stays by value (three words), as generated.

## Deviations and notes

- `matches_pseudo_class` (one 680-line C++ switch) is split: its cases from `:valid` on are
  `matches_pseudo_class_forms` (selector_engine_3), called from the switch, each case unchanged.
- The C++ lambdas are private functions named after their enclosing function (capture structs
  where they capture: `CssSelectorSpecificityCounts`, `SelectorEngineMatchesAttributeMatch`);
  `ScopeGuard`s are `defer`s; `fast_matches`' `backtrack_state` struct is two locals.
- `is_one_of` over the 46 case-insensitive HTML attribute names is a local array of the
  interned names.
- `language_range_matches_tag` walks the split vectors by index (C++ iterators).
- Donor behavior kept and pinned by a test: the fast path's descendant walk does not stop at a
  shadow host (`parent_element()`), where the full matcher's `traverse_up` does.

## Tests

- `tests_selector_cases` (105 cases) + `tests_selector`: a local oracle
  (`luce-browser-tools/oracles/luce-browser-engine/selector_engine`: `selectors.cpp` links the
  reference build's LibWeb objects as r31's, `selector_cases.txt`, `build.sh`,
  `gen_selector_cases.py`) runs `parse_selector` and prints, per selector, serialize, specificity
  (incl. the 255 clamp), the fast-match / ancestor-filter flags and the ancestor hashes, the
  sibling invalidation distance, the nesting / webkit / slotted / part flags, the target
  pseudo-element, the contained pseudo-classes and `dump_selector`; nested selectors
  (`adapt_nested_relative_selector_list`) absolutized against `:is(.p, #q)` and `:has(.y)` (the
  invalid-contents error); An+B patterns; @page selector lists; the ErrorReporter's errors.
  Focused tests: PseudoClassBitmap, PageSelector, PseudoElementSelector, `relative_to` and the
  caches.
- `tests_selector_engine_cases` (13 trees, 231 queries) + `tests_selector_engine`: the matching
  oracle (`gen_matching.py`, `matching_cases.txt`) runs a Text test through the reference build's
  `test-web --rebaseline` and records `querySelectorAll` results; the Luce test builds each tree
  by hand in a document shaped as the reference's (HTMLElement's constructor for each element,
  with the element classes `:root`, `:heading` and `:open` tell apart; the attribute list with
  id/class applied as `attribute_changed` does; raw tree insertion) and runs each query through
  the port's `ParentNode::querySelectorAll`. Covered: type/universal/id/class, every attribute
  match and case type (and the HTML case-insensitive attributes), first/last/only child and of
  type, :nth-*() with An+B and `of S`, :empty, :root, :scope, all combinators, :not/:is/:where,
  :has with every relative combinator, :lang ranges and inheritance, :defined, :open, the
  state pseudo-classes that are false in a static document, pseudo-elements, invalid and
  namespaced selectors. Focused tests pin the :has() result cache and its counters, the
  per-element involvement metadata, fast path vs full matcher (with backtracking), shadow hosts,
  pseudo-element targets, quirks-mode classes and RFC 4647 language ranges.
