## Conventions other regions will meet

- **Mixin vtables.** `dom_element_construct` constructs the ARIAMixin base and points the three
  mixin vtables (`slottable_mixin`, `aria_mixin`, `animatable`) at Element's tables. Every
  subclass constructor (r22 HTMLElement and the HTML elements, r55/r56 SVG, MathML) must move
  them to its own generated tables (`html_input_element_aria_mixin_vtable`, …) after calling its
  base constructor, as r14's DOMException does for `serializable`.
- **From a mixin to its element**: `dom_element_from_aria_mixin(base)` (and the private
  `dom_element_from_slottable_mixin`) subtract the mixin's offset in `DomElement`; every subclass
  embeds Element first, so the offset is the same.
- **Private helpers other fragments may reuse**: `dom_element_document`, `dom_element_realm`,
  `dom_element_abstract_element(element, pseudo_element)`, `DomElementIsAsciiWhitespace` (the
  `split_view_if(Infra::is_ascii_whitespace)` predicate), `dom_element_string_equals_ignoring_ascii_case`,
  `dom_fly_string_is_one_of_fly_strings`.
- **`heap.allocate<T>()` of layout nodes** (create_layout_node_for_display_type) uses the generated
  `realm_create_layout_*` helpers in the document's realm (a layout node's `initialize` is
  JS::Cell's, empty). PseudoElement(TreeNode) cells come from the new
  `heap_allocate_dom_pseudo_element(_tree_node)` in `dom/types_pseudo_element.lucb` (over r14's
  `web_heap_allocate_cell`).
- `Element::initialize` calls `web_set_prototype_for_interface(base, realm, BindInterfaceName.element)`
  then EventTarget's initialize (ParentNode and Node do not override it).
- Template callbacks: `for_each_numbered_item_owned_by_list_owner(_const)` take
  `ak.Function1[DomElement*, ak.IterationDecision]`; `create_element_internal` takes the interface
  as `func(DomDocument*, DomQualifiedName) -> DomElement*` (`DomElementInterface`).
- `recompute_inherited_style`'s `HashMap<size_t, RefPtr<StyleValue>>` is a Vector of pairs: the
  indices are visited in increasing order once each, and the only use is OR-ing invalidations.

## Deviations and notes

- `follow_the_hyperlink` stops at step 13 with `trap("unported (P2): …")`: `Navigable::NavigateParams`
  is opaque in phase 1.
- The JS-facing steps (custom element upgrade/construct, the connectedMoveCallback native
  function, TrustedTypes) call the phase-3 seams above; DOMExceptions go through `idl_throw`,
  `vm.throw_completion<TypeError>` through r14's `vm_throw_completion`.
- `client_top`/`client_left` and the two `scroll_top`/`scroll_left` pairs stay separate
  functions, as in C++.
- `scrollIntoView`'s "Do nothing" branches are expressed by guarding the following `else if`s
  with `if not both_outside:`; the `if (true)` FIXME branch keeps only its body.
- `css_display_to_string` is printed with `ak.dbgln` for unsupported displays, as C++ does with dbgln.

## Tests

`dom/tests_element.lucb` (18 tests, run by `./test.sh`): the name validity checks against values
taken by compiling the donor's `is_valid_*` and `is_valid_custom_element_name` against the
reference build's AK (28 names, including non-ASCII, controls and reserved names); every
exception of validate-and-extract and toggleAttribute (with r14's test VM and realm); the
attribute queries of an element without attributes; has_class in both case modes; the
removed-attribute bookkeeping; the structural flags and the parent's backward flag; the
tree-counting flag on the parent; custom element states; dir-driven directionality (auto with no
text is 'ltr'); translation mode; scroll offsets; cached lang and ordinal values; an element's
target (the C++ looks for the three-character sequence "\t\n\r" before '<'); the mixins' way back
to their element; pseudo-element queries without data; the factory's local-name tables.

Elements are built by hand (r15's `test_node`), since constructing one traps in r19's EventTarget
constructor (and in r13b's `aria_mixin_construct`, a defaulted constructor still stubbed). Once
r17-r19 and r18's QualifiedName land, scenario tests should cover: create_element for the HTML,
SVG and MathML tables and unknown/custom names, the attribute API over a NamedNodeMap
(set/toggle/remove, attribute_changed for id/class/name/dir/part/slot), validate_and_extract's
success path, attachShadow, matches/closest, the directionality algorithms over text, list
ordinals and `is_unknown_html_element` with interned tag names.
