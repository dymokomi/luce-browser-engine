## Deviations and notes

- **Donor quirks kept**: `normalize_line_breaks` drops a CR LF pair (`consume_until("\r\n")` stops
  at the CR and `ignore(2)` skips both: `"a\r\nb"` → `"ab"`, pinned by the oracle);
  `mail_with_headers` discards the result of `headers.replace("+", "%20")`.
- `HTMLFieldSetElement::type` / `HTMLOutputElement::type` return a new String each time (C++
  caches it in a function-local static; a module global is not scanned by the collector).
- `TRY_OR_THROW_OOM` is `try` (the only failure is out of memory).
- A FACESubmissionValue's list of entries is cloned when set (C++ copies the variant).
- Lambdas: the select-event task and the planned navigation task are capture structs allocated
  with `new`; the HTMLCollection / RadioNodeList filters take the form or a capture struct as
  context; `parse_autocomplete_attribute`'s step_default / step_done are functions over their
  captures; `supported_property_names`' SourcedName is a local struct sorted with AK's quick_sort.
- `HTMLLabelElement::activation_behavior`'s ScopeGuard block has no early exit, so the click flag
  is unset at its end.

## Tests

Ladybird has no unit tests for these files. `tests_html_forms_1` (7): factory construction and
the mixin tables and answers of form / fieldset / legend / label / output; **garbage collection
with HTML elements alive** (a document tree of form, fieldset, legend and output survives two
collections, a collected detached form owner leaves the weak `m_form` null, a ValidityState and
an ElementInternals visit their element); resetting the form owner (ancestor, the form attribute
naming another form or nothing, removing the attribute, removal from the tree, the parser
inserted flag); enabled and nested disabled fieldsets with their legends, the fieldset's
elements; the constraint validation API, setCustomValidity's newline normalization, ValidityState
over the FACE flags; formAction / action defaults; ElementInternals' eight NotSupportedErrors.
`tests_html_forms_2` (8): the autofill processing model on 23 attribute values (expected values
from a local oracle running the donor's algorithm against the reference build's AK, including
the hint set's HashTable order), tokens, the IDL attribute and the field categories; the text
control selection over a test mixin (offsets, clamping on a value change, direction, the
stringifier, setRangeText, IndexSizeError); normalizing line breaks (oracle values); name-value
pairs, text/plain and multipart/form-data of string entries; the form's method / enctype /
action, elements and length, indexed values, submittable elements, validation, the constructing
entry list flag, relList and picking an encoding; supported property names with the past names
map and namedItem; a label's control by `for` and by descendant; output's value and defaultValue.

The GC test collects with test tables for the document (its visit reaches StyleScope, r39, and
members a phase-1 test document leaves null, such as its FontFaceSet) and heap test pages
(Page::visit_edges is r28's; tests_document's pages are off-heap cells the collector cannot
mark). It used to run under `with heap`, because WeakImpls held only from C-heap memory were
recycled by a collection. Since fix/weak-impls a Weak stays valid wherever it is held
(DESIGN.md §3.7), and the test runs with the test's own allocator.
