Region r37 ports `CSS/CSS.cpp`, `StyleSheet`, `CSSStyleSheet`, `StyleSheetList`,
`StyleSheetIdentifier`, `MediaList`, `CSSRule`, `CSSRuleList`, every CSS rule class
(`CSSGroupingRule`, `CSSConditionRule`, `CSSMediaRule`, `CSSSupportsRule`, `CSSContainerRule`,
`CSSLayerBlockRule`, `CSSLayerStatementRule`, `CSSNamespaceRule`, `CSSImportRule`, `CSSStyleRule`,
`CSSNestedDeclarations`, `CSSPageRule`, `CSSMarginRule`, `CSSPropertyRule`, `CSSCounterStyleRule`,
`CSSFontFaceRule`, `CSSFontFeatureValuesRule`, `CSSFontFeatureValuesMap`, `CSSFunctionRule`,
`CSSFunctionDeclarations`), the declaration blocks (`CSSStyleDeclaration`, `CSSStyleProperties`,
`CSSDescriptors`, `CSSFontFaceDescriptors`, `CSSPageDescriptors`, `CSSFunctionDescriptors`,
`Descriptor`) and the generated `GeneratedCSSStyleProperties`. It also ports `CSSKeyframesRule`
and `CSSKeyframeRule` (animations, outside the phase-1 files) because the parser makes them. The
stub fragment `stubs/stub_r37_css_sheets.lucb` is gone; every one of its functions is ported.

## What other regions must know

### Cells and mixins

- Rules, sheets, lists and declaration blocks are cells made with the generated
  `realm_create_*`; `css_*_create` are the C++ `create`s.
- `CSSImportRule` is also a `CSSStyleSheet::Subresource`: the mixin is `rule.subresource`, its
  vtable is installed by the constructor, and `css_import_rule_from_subresource` is C++'s `this`
  adjustment. **types_css_import_rule**: the mixin vtable's `visit_edges` slot is filled
  (`css_import_rule_subresource_visit_edges_impl`), because CSSImportRule::visit_edges overrides
  both bases' virtuals.
- `CSSStyleProperties`' `GeneratedCSSStyleProperties` mixin is `props.generated_css_style_properties`
  (vtable installed by the constructor); the generated accessors take the mixin
  (`bind_generated_css_style_properties_color(&props.generated_css_style_properties)`).
- `CSSStyleSheet.m_pending_image_values` holds `WeakPtr<ImageStyleValue>`s over blobs: a style
  value is a heap blob, so the Weak is made to its Cell header (`css_weak_image_style_value`,
  css_style_sheet_2). **r34**: style values must be heap blobs for this (they are, under `with
  heap`).

### CSSKeyframesRule and CSSKeyframeRule (types_css_keyframes_rule)

The skeleton left both opaque (outside the phase-1 closure). They are now declared in the
generator's shape by hand, with CSSRule's own class id (8, which no object has): `is<CSSRule>`
holds for them and `is<>` of every other CSSRule subclass does not; their own
`is_/as_/as_if_css_keyframe(s)_rule` test the rule type, as `CSSRule::fast_is` does. The skeleton
should give them class ids when it is next run with them in scope.

### Where phase-1 paths stop now (other regions' stubs)

- Every mutation of a sheet that has owners or reaches `invalidate_owners`
  (insertRule/deleteRule/replaceSync on CSSStyleSheet, selectorText on a rule in a sheet,
  MediaList on a sheet, setProperty on a rule's declarations, enabling/disabling a sheet) reaches
  r42's `invalidate_style_for_style_sheet_owners` / `determine_shadow_root_stylesheet_effects`.
  CSSRuleList's "insert/remove a CSS rule" and CSSGroupingRule's insertRule/deleteRule do not.
- `@namespace` (every form: the parser tries `parse_url_function` first), `@import` and
  `@function` with parameters stop in r32 (`parse_url_function`, `parse_dashed_ident`); `@media`,
  `@supports` and `@container` in r42/r32; declarations with values in r33/r34.
- StyleSheetList: adding an enabled sheet loads its fonts (r41's `FontComputer`); removing one
  unloads them; `CSSStyleSheet::set_disabled` invalidates (r42).
- `@font-feature-values`: CSSFontFeatureValuesMap keeps its entries in a JS::Map as Ladybird
  does, so creating the rule traps in `js_map_create` until phase 3.
- `CSSImportRule::fetch` (when an @import gets a parent sheet) reaches the phase-2 Fetch stubs.

## Deviations and notes

- Lambdas are private functions with capture structs; the `ScopeGuard`s are `defer`s.
- `CSSStyleSheet::namespace_uri(StringView)` looks the prefix up as a FlyString (the HashMap's
  StringView-compatible lookup hashes and compares the same bytes).
- `GeneratedCSSStyleProperties`' Luce names come from the skeleton's naming of the C++ names
  (`float_` is `float`); the generator applies `luce_snake` and the test compares nothing but the
  regenerated file, so the names were checked once against the stub fragment's 898 names.

## Tests

- `tests_css_sheets_cases` (82 cases) + `tests_css_sheets`, `tests_css_sheets_2`: a local oracle
  (`luce-browser-tools/oracles/luce-browser-engine/css_sheets`: `oracle.cpp` links the reference
  build's LibWeb objects and runs in the internal CSS realm, `cases.txt`, `build.sh`,
  `gen_luce_cases.py`) parses each sheet and prints every rule's class, type for bindings,
  internal type and cssText recursively, Dump.cpp's dump of rules, CSSRuleList insert/remove
  with their exceptions, CSSGroupingRule insertRule/deleteRule, selectorText of free style rules
  and page rules, the cascade layer names (internal qualified names of blocks, statements and
  style rules), and focused objects: empty and resolved CSSStyleProperties (every getter,
  setProperty/removeProperty/cssText and their NoModificationAllowedErrors, the generated
  accessors), descriptor blocks and @font-face, @counter-style names, @property, @container
  conditions and effective rules, @import serialization and dump, keyframes, nested
  declarations, MediaList and StyleSheet state, margin and feature names, StyleSheetIdentifier,
  loading-state names and `CSS.escape`. All match. 52 more cases (marked `!` in cases.txt:
  sheet insertRule/deleteRule/addRule/selectorText, @namespace, @function parameters) run in
  the oracle and wait for r32/r42; `gen_luce_cases.py` leaves them out.
- `tests_css_sheets_3`: parent rule and style sheet links, effective-rule traversals,
  StyleSheetList with a disabled sheet, the critical-subresource loading state, the mixin link.
