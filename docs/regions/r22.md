## What other regions must know

### Constructing HTML elements (r21's parser, r23–r27's element classes, r16's factory)

- `html_element_construct(this, document, qualified_name)` runs Element's constructor, then
  constructs the GlobalEventHandlers, `HTMLOrSVGElement<HTMLElement>` and FormAssociatedElement
  bases: the two `FACESubmissionValue` variants start `.empty` (C++'s `Variant` default; the
  zero bits would be `file_api_file`), and **every mixin table moves to HTMLElement's**
  (`slottable_mixin`, `aria_mixin`, `animatable`, `global_event_handlers`,
  `form_associated_element`; the two HTML mixins' `class_id` is the cell's). Each subclass
  constructor calls it and then moves the five tables to its own generated
  `html_<class>_*_vtable`s, as `html_unknown_element_construct` does.
- `realm_create_html_element` / `realm_create_html_unknown_element` work in a settings realm
  (r29) with a heap document: `dom_create_html_element` (the factory's tag dispatch) makes
  HTMLElement for the 50 sectioning/phrasing names and valid custom names, HTMLUnknownElement for
  the rest. `dom_create_element` itself still traps in r42
  (`invalidate_style_after_custom_element_state_change`: the element's initial state is
  `undefined` and creation sets `uncustomized`).
- `html_element_initialize_impl` is the `Base::initialize` of every HTML element class.

### On the critical path now (other regions' stubs every HTML element reaches)

- **r23**: `FormAssociatedElement::is_form_associated_element` (every `attribute_changed`,
  `inserted`, `removed_from`, `moved_from` of an HTML element), `FormAssociatedElement::visit_edges`
  (every HTML element's `visit_edges`, so **any collection with an HTML element alive traps until
  r23 lands**), `is_autocapitalize_and_autocorrect_inheriting`, `enabled` (click()). The tests
  use a FormAssociatedElement table answering C++'s `false`.
- **r42**: `invalidate_style_after_attribute_change` (after every attribute change),
  `invalidate_style_after_directionality_change` (dir), `invalidate_style_after_hyperlink_state_change`.
- **P2**: `PolicyList::contains_header_delivered_policy` (HTMLOrSVGElement's insertion steps of a
  browsing-context-connected element); **r28**: the document's base URL in
  `encoding_parse_url` (HTMLHyperlinkElementUtils with an href).

### Mixins

- **HTMLOrSVGElement<T>** keeps its generic signatures (`this: HtmlOrSvgElement[T]*`); it is at
  the same offset in HTMLElement, SVGElement and MathMLElement (asserted at module level), and
  `static_cast<ElementBase*>(this)` is that offset. r55 (SVG) and r13b (MathML) call
  `html_or_svg_element_attribute_changed(&this.html_or_svg_element, ...)` etc. as HTMLElement does.
- **LazyLoadingElement<T>**: the functions take the element, `[T: IsDomElement &
  HasHtmlLazyLoadingElement[T]](this: T*)` (the stub took the mixin, from which the element cannot
  be reached: it sits at different offsets in img and iframe). `HasHtmlLazyLoadingElement[T]`
  (new, `types_lazy_loading_element`) is declared on HTMLImageElement and HTMLIFrameElement's
  types with a one-line `html_lazy_loading_element()`; r26/r27 call e.g.
  `html_lazy_loading_element_will_lazy_load_element(this)` with `this: HtmlImageElement*`.
- **GlobalEventHandlers / WindowEventHandlers**: the getters and setters go through the virtual
  `*_to_event_target`; HTMLElement answers itself. The pure virtuals trap.

## Deviations and notes

- **Donor quirks kept**: `parse_a_time_component` checks `hour > 59` where the spec says minute
  (minutes 60-99 parse); `hide_popover`'s cleanup steps test `if (nested_hide)` where the step says
  "if nestedHide is false"; `is_valid_date_string` (and so local date-and-time strings) with a
  whitespace-led year VERIFY-fails in `parse_ascii_digit` (`" 2020-01-01"`), and the port traps.
- `parse_floating_point_number`'s `goto`s are labeled once-loops (`break conversion`,
  `break fraction`); the C++ `exponent *=` narrowing to i16 is spelled out.
- HTMLHyperlinkElementUtils mutates `m_url` through a reference to the optional's value; the port
  takes the URL out, changes it and stores it back (a plain Url copy shares its CopyOnWrite data).
- `rendered_text_collection_steps` names its enum cases in full (`# LUCE-BUG:
  enum_case_context_from_generic_argument`, below).
- Lambdas: show_popover's closeAction is a native function whose context is the element;
  getEnabledState is a `gc.Function0[bool]`; the popover toggle task's captures are allocated with
  `new`; checkAncestor is a function over a capture struct; labels()' filter's context is the
  element.

## Compiler issues

- `enum_case_context_from_generic_argument` (`luce-browser-tools/compiler-issues/`): a `.case`
  argument whose parameter type is a generic parameter already fixed by an earlier argument
  (`ak.vector_append_t(&items, .utf16_string(...))`) gets no enum context. Worked around in
  `html_element_1` by naming the enum (tagged `LUCE-BUG`).
- Language note (not filed): an ASCII character literal adapts to `u8` only, so `u16` code units
  are written `(u16)'-'`.
